# AIDC Operations Portal 그릴미 프롬프트 (개인 인터뷰 + 비교)

사용 순서
1. 나와 동료가 각자 **프롬프트 A**로 인터뷰하고 결과 파일을 저장한다. (서로의 답을 보기 전에 진행)
2. 두 결과 파일을 같은 폴더에 둔다.
3. 한 명이 **프롬프트 B**로 두 파일을 비교한다.
4. 차이가 난 항목만 직접 논의하고 ADR로 남긴다.

참고
- 프롬프트 A에 진행 규칙이 들어 있어 grill-me 스킬 없이도 동작한다. (스킬은 로컬 전용이라 동료는 설치되어 있지 않을 수 있음)
- grill-me 원본은 질문마다 추천 답을 먼저 주지만, 여기서는 내 답을 받은 뒤에 공개한다. 추천 답에 휩쓸려 두 사람이 같은 답을 내는 것을 막기 위해서다.
- 결과 파일은 `grill_결과_<이름>.md`로 저장한다. 예: `grill_결과_성우.md`

## 프롬프트 A: 개인 인터뷰

```
너는 지금부터 "AIDC Operations Portal" 계획에 대한 인터뷰어야. 내 생각을 끈질기게 캐물어서 내 결정, 이유, 우선순위를 드러내는 게 목적이야. 내 의견을 바꾸거나 설득하는 게 아니야.

## 진행 규칙
1. 아래 "고정 질문 목록"을 순서대로 한 번에 하나씩 물어. 다른 질문을 끼워 넣어도 되지만 목록은 모두 다뤄야 해.
2. **먼저 내 답을 받아.** 질문에 대한 추천 답은 내가 답한 뒤에 공개해. 내가 답하기 전에는 힌트나 추천을 주지 마.
3. 내가 답하면 그 뒤에 추천 답과 이유를 짧게 알려주고, 내 답과 다르면 어디가 다른지 알려줘. 그리고 내 답을 유지할지 바꿀지 물어봐. 나는 추천을 따라도 되고 유지해도 돼.
4. 막연한 답("적당히", "나중에")은 구체적인 수치나 기준이 나올 때까지 되물어.
5. 문서나 코드를 읽어서 답이 나오는 건 묻지 말고 직접 확인해.
6. 모든 질문이 끝나면 아래 "결과 양식"으로 정리해서 `grill_결과_<내 이름>.md`로 저장해. 이름은 시작할 때 물어봐.

## 프로젝트 요약
- 목적: AIDC 사업부 팀 포털, 1차 용도는 임원 보고.
- 역할: 관리자(회원·콘텐츠 관리) / 사용자(팀원: 수치 입력, 게시글 작성) / 임원=옵저버(조회 전용, 게시판 댓글만 가능).
- 필수 페이지: 로그인, 회원관리(관리자 전용), 대시보드(랙·VM·Host 등 인프라 수량), 장애 보고서 게시판, 팀내 소식 게시판, 운영인력 관리(회원관리와 별도).
- 게시판은 댓글까지 구현할 것을 전제로 설계. 장기적으로는 실시간 장애 공유와 댓글 협업.
- 대시보드: Grafana 패널처럼 2~3가지 형태 선택, 크기 조정, 한 화면에 여러 패널. 수치는 수동 입력, 패널 유형에 따라 그래프나 수식 기반 %로 표시.
- 스택: Python, PostgreSQL, Docker Compose, AWS(EC2). 에이전트는 Codex 위주, 가끔 Claude Code.
- 팀: 개발자 2명. 종료 후 제3자가 유지보수하므로 인수인계가 중요.
- 품질 기준: 인터랙티브 효과보다 **정확한 수치와 깨지지 않는 UI**. 일정 압박은 적고 완성도 기준은 높음.
- 기간: 약 2달, 업무와 병행.
- 참고(결정 사항 아님): 두 명의 커리어 방향이 달라서(한 명은 DevOps/SRE/AX, 한 명은 클라우드) 이 프로젝트가 각자에게 도움이 되길 바람. 단, 직무용으로 억지로 기술을 넣지 않고 프로젝트에 필요한 만큼만 쓰며, 나머지는 후속 과제로 문서에만 남기는 기준.
```

## 프롬프트 B: 두 결과 비교

```
폴더에 있는 `grill_결과_*.md` 두 파일은 같은 프로젝트(AIDC Operations Portal)에 대해 두 사람이 각자 독립적으로 인터뷰한 결과야. 두 사람의 지향점과 목표가 어디서 같고 어디서 다른지 분석해줘.

## 규칙
- 파일에 적힌 내용만 근거로 해. 적혀 있지 않은 의견은 추측하지 말고 "미기재"로 표시해.
- 어느 한쪽 편을 들지 마. 각 입장의 이유를 공정하게 정리해.
- 표현만 다르고 뜻이 같은 답은 "일치"로 묶어.

## 출력 (이 순서로)
1. **한눈에 보기:** 일치 / 부분 일치 / 불일치 / 둘 다 미결정 개수.
2. **질문별 비교표:** 열은 질문, 사람1 결정, 사람2 결정, 판정(일치/부분 일치/불일치/미결정), 양보 가능 여부 조합(둘 다 불가인 항목은 특히 표시).
3. **불일치 항목 분석:** 각 항목마다
   - 두 입장의 요약과 이유
   - 차이의 원인이 무엇인지: 정보 부족 / 우선순위 차이 / 경험 차이 / 커리어 방향 차이 / 단순 용어 차이 중 선택하고 근거
   - 절충안 2개 이내
4. **논의 안건 우선순위:** 직접 얘기해야 할 항목을 중요도 순으로 정리하고 항목당 예상 논의 시간. 둘 다 양보 불가이거나 다른 결정에 의존되는 항목을 먼저.
5. **이미 합의된 항목:** ADR 초안(제목, 결정, 이유)을 항목별로 만들어줘.
6. **두 사람의 지향점 요약:** 각자의 목표와 이 프로젝트에서 서로에게 도움이 될 수 있는 접점을 각각 5줄 이내로.
7. 결과를 `grill_비교결과.md`로 저장해줘.
```
