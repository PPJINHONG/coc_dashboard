# AI 지침은 어디에 적나요?

## 위치별 역할

공통 규칙은 한 곳에만 적고, 역할 파일에는 그 역할에 필요한 내용만 둡니다.

```text
내 계정
└─ ~/.codex/AGENTS.md                   여러 프로젝트에서 쓸 개인 취향

coc_dashboard/
├─ AGENTS.md                           팀 공통 작업 원칙(구조·데이터 보호·권한·반영 기준)
├─ .codex/
│  ├─ design-system.md                 화면 디자인 규칙
│  └─ agents/verifier.toml             별도 검토 역할 지침
└─ docs/                               사람이 따라 하는 실행·구조·협업 설명
```

| 위치 | 적을 내용 |
| --- | --- |
| 홈의 `~/.codex/AGENTS.md` | 말투 등 개인의 여러 프로젝트 공통 취향 |
| 프로젝트 `AGENTS.md` | 작업 범위, Git 수동 원칙, 폴더 구조 규칙, 설정·데이터 보호, 권한 정책, 반영·확인 기준 |
| `.codex/design-system.md` | 색상·글꼴·표·카드 등 화면 규칙 |
| `.codex/agents/verifier.toml` | 검토할 때 찾을 문제와 검토 역할의 수정 제한 |
| `docs/` | 실행 명령, 구조 설명, 협업 절차 |

전역 지침과 프로젝트 지침은 함께 적용되고, 같은 주제에 다른 지시가 있으면 더 구체적인 프로젝트 지침이 우선합니다. 팀 공통 규칙을 개인 전역 파일에만 두지 않습니다. [공식 지침 안내](https://learn.chatgpt.com/docs/agent-configuration/agents-md)

## 평소 작업

바꾸고 싶은 기능과 기대하는 동작을 알려주면 주 에이전트가 구현·Docker 반영·확인까지 진행합니다. 다른 에이전트를 자동으로 부르지 않습니다.

- "인프라 자원 탭에 ○○ 열 추가"처럼 **기능 이름**으로 요청하면 그 기능 폴더(`frontend/src/features/<기능>/`, `backend/features/<기능>/`) 안에서 작업합니다.
- 공통 파일(`app/`, `shared/`, 공통 앱, 설정)을 바꿔야 하면 에이전트가 이유를 알려 줍니다. 상대와 동시에 작업 중이면 [협업 규칙](parallel-development.md)대로 먼저 공유합니다.
- 결과는 바꾼 내용·확인 결과·남은 문제만 짧게 전달합니다.
- 핵심 요구사항이 모호하거나 데이터 삭제·운영 배포가 필요하면 질문합니다.

Git 상태와 이력은 AI가 확인할 수 있습니다. 브랜치 전환·스테이징·커밋·푸시·병합은 사람이 직접 하며, 별도로 요청했을 때만 AI가 실행합니다.

## 별도 검토가 필요할 때

“이번 변경을 별도 에이전트로 검토해 줘”라고 요청하면 `verifier`를 사용합니다. 검토 역할은 요청대로 구현됐는지, 기존 기능과 다른 기능 폴더에 영향이 없는지 확인하고 수정할 내용은 주 에이전트에 전달합니다. 일반 작업의 확인은 주 에이전트가 직접 합니다. [공식 역할 설정 안내](https://learn.chatgpt.com/docs/agent-configuration/subagents)

## 지침을 추가할 때

- 개인 취향이면 전역 파일, 팀원 모두 지킬 원칙이면 `AGENTS.md`, 화면 규칙이면 `design-system.md`, 특정 역할에만 필요하면 그 역할 파일에 적습니다.
- 긴 설명은 `docs/`에 쓰고 지침에는 링크만 둡니다. 같은 규칙을 여러 파일에 복사하지 않습니다.
- 한 번 있었던 작업 기록(언제 무엇을 지웠는지 등)은 지침에 쌓지 않고 [운영 데이터 설계의 변경 기록](../02-development/operations.md#5-과거-구조-변경-기록)이나 Git 이력에 남깁니다.
