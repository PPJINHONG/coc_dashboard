# AI 지침은 어디에 적나요?

[문서 목록](../README.md)

## 세 가지 위치의 역할

프로젝트 최상위 `AGENTS.md`와 프로젝트 안의 `.codex/agents/`는 서로 다른 용도입니다. 공통 규칙은 한 곳에만 적고, 역할 파일에는 그 역할에 필요한 내용만 둡니다.

```text
내 계정의 설정
└─ ~/.codex/AGENTS.md                   여러 프로젝트에서 쓸 개인 취향

coc_dashboard/                         이 프로젝트
├─ AGENTS.md                           팀 공통 작업 원칙
├─ .codex/
│  └─ agents/
│     └─ verifier.toml                 별도 검토 역할에만 필요한 지침
└─ docs/03-collaboration/
   └─ agent-workflow.md                지금 읽는 사용 안내
```

| 위치 | 여기에 적을 내용 |
| --- | --- |
| 홈의 `~/.codex/AGENTS.md` | 선호하는 말투·UI 스타일 등 개인의 여러 프로젝트에 공통인 취향 |
| 프로젝트의 `AGENTS.md` | 자율 작업 범위, Git 수동 원칙, 이 프로젝트의 설정·데이터 보호, 확인과 보고 기준 |
| 프로젝트의 `.codex/agents/verifier.toml` | 검토할 때 찾을 문제, 근거를 제시하는 방법, 검토 역할의 수정 제한 |
| `docs/` | 실행 명령, 상세 설명, 사람이 보고 따라 할 사용법 |

전역 지침과 프로젝트 지침은 함께 적용되고, 같은 주제에 다른 지시가 있으면 더 구체적인 프로젝트 지침이 우선합니다. 전역 파일은 다른 프로젝트에도 영향을 주므로 팀 공통 규칙을 개인 전역 파일에만 두지 않습니다. [공식 지침 안내](https://learn.chatgpt.com/docs/agent-configuration/agents-md)

## 평소에는 이렇게 작업합니다

바꾸고 싶은 기능과 기대하는 동작을 알려주면 주 에이전트가 구현과 필요한 확인까지 진행합니다. 기본 절차에서 다른 에이전트를 자동으로 호출하지 않습니다.

- 작은 수정은 바뀐 부분을 중심으로 확인합니다.
- 화면·API·DB 연결이 바뀌면 해당 동작도 확인합니다.
- 결과는 바꾼 내용·확인 결과·남은 문제만 짧게 전달합니다.
- 핵심 요구사항이 모호하거나 데이터 삭제·운영 배포가 필요하면 질문합니다.

Git 상태와 이력은 AI가 확인할 수 있습니다. 브랜치 전환·스테이징·커밋·푸시·병합은 사람이 직접 하는 것이 기본이며, AI에게 별도로 요청했을 때만 실행합니다.

## 별도 검토가 필요할 때

“이번 변경을 별도 에이전트로 검토해 줘”라고 요청하면 `verifier`를 사용할 수 있습니다. 검토 역할은 요청대로 구현됐는지와 기존 기능에 문제가 생기지 않았는지 확인하고, 수정할 내용은 주 에이전트에 전달합니다.

일반 작업의 확인은 주 에이전트가 직접 합니다. 매번 검토 역할을 따로 실행하거나 인계 양식·보고서 파일을 만들 필요는 없습니다. [공식 역할 설정 안내](https://learn.chatgpt.com/docs/agent-configuration/subagents)

## 지침을 추가할 때

- 여러 프로젝트에 필요한 개인 취향이면 전역 파일에 적습니다.
- 팀원 모두 지켜야 하는 프로젝트 원칙이면 프로젝트 `AGENTS.md`에 적습니다.
- 특정 역할에만 필요하면 해당 역할의 TOML 파일에 적습니다.
- 설명이 길어지면 `docs/`에 쓰고 필요할 때 찾아봅니다. 같은 규칙을 여러 파일에 복사하지 않습니다.

기존 총괄·구현 전용 설정은 제거하고 공통 작업을 한 에이전트가 처리하도록 정리했습니다. 역할 파일에 반복되던 기본 규칙도 공통 파일로 모아, 작은 작업에 불필요한 분업과 반복 안내가 생기지 않도록 했습니다.
