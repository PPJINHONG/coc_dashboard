# COC dashboard 디자인 규칙

모든 기능과 관리 화면은 이 규칙과 기존 공통 컴포넌트를 따른다. 경로는 `frontend/src/` 기준이다.

## 파일 위치

- 색상·글꼴 토큰: `shared/styles/tokens.css`. 버튼·입력·패널·배지·제목: `shared/styles/base.css`. 표·필터·편집 표·모달: `shared/styles/sections.css`.
- 공통 부품: `shared/components/`(Icon·Panel·Modal·DataTable·FieldInput·ErrorMessage·AccountField), 목록 화면: `shared/sections/`(SectionPage·SectionEditor·RecordsAdmin).
- 뼈대·홈·탭 관리·초대·로그인 스타일은 `app/*.css`, 기능 전용 스타일은 `features/<기능>/<기능>.css`에 둔다. 기능 CSS의 클래스는 기능 고유 이름으로 시작하고(예: `inventory-`, `resource-`, `staff-`, `issue-`) 다른 기능 클래스를 덮어쓰지 않는다. 여러 기능이 같이 쓰는 모양은 `shared/styles/`에 추가한다.
- 적용 순서는 `base.css` → 로그인 → 뼈대·홈·공통 표 → 기능 CSS → `tokens.css`(마지막)다. 순서를 바꾸면 같은 우선순위 규칙의 결과가 달라지므로 바꾸지 않는다.

## 기본 표현

- 화이트 모드만 제공한다. 흰 패널, 옅은 회색 배경, 선명한 1px 청회색 테두리와 절제된 파란색 강조를 기본으로 한다.
- 영문·숫자는 자체 제공 `/fonts/InterVariable.woff2`, 한글은 같은 서버의 `/fonts/PretendardVariable.woff2`(Pretendard v1.3.9)를 사용해 맥·윈도우 모두 같은 파일로 표시한다. Inter를 먼저 선언하며 OS 설치 폰트나 외부 CDN에 의존하지 않는다. 모든 입력·버튼·표·모달도 같은 글꼴을 쓴다. OFL 라이선스는 `frontend/public/fonts/`에 보관한다.
- 여백은 4/8px 배수, 패널 간격은 16~24px를 우선한다. 본문 13~14px, 표 12~13px, 보조 정보 11~12px를 기준으로 한다.
- 전체 텍스트는 검정·진한 남색(`#111d25`, `#142536`, `#1d334a`)만 사용한다. 설명·날짜·미입력·플레이스홀더·비활성 버튼에도 회색 글자나 opacity로 흐리게 하는 표현을 쓰지 않는다. 채운 파란색 버튼의 흰 글자와 오류의 진한 빨간색은 예외다.
- 강조·선택·연결은 파란색 계열을 기본으로 한다. 권역별 요청작업의 상태 구분은 Open 빨강, In Progress 파랑, Completed 회색, TODAY 검정을 사용하고 텍스트 라벨을 함께 표시해 색에만 의존하지 않는다.
- 아이콘은 `shared/components/Icon.tsx`의 SVG를 재사용한다. 이모지·무작위 색상·장식용 그라데이션·큰 그림자를 추가하지 않는다. 브랜드는 내부가 빈 하늘색 구름 SVG를 같은 선 굵기로 쓴다.

## 화면 구조

- 기능 화면: 좌측 사이드바, 상단 경로/액션, 제목, 필터·요약, 본문 순서. 사이드바는 접을 수 있고 좁은 화면에서는 아이콘 중심으로 바뀐다. 사이드바는 홈·리포트 다음 업무 기능·변경 이력이며 DB 관리는 구분된 관리자 메뉴다. 사이드바와 제목 옆에 레코드 건수나 연결됨 표시를 두지 않는다.
- 홈: `COC dashboard` 제목·한 줄 설명, 주요 기능(넓은 인프라 미리보기와 리포트·권역별 요청작업 카드), 3열 전체 기능 카드 목록. 검색·별도 지표 박스·저장 시간 박스는 두지 않는다. 카드는 흰 배경, 1px 중립색 경계, 6px 모서리, 24px 안쪽 여백, 18px 제목·14px 설명, 낮은 불투명도의 부드러운 그림자를 쓴다. 주요 기능 제목은 16px·설명은 12px이며 문구를 줄이거나 한 줄로 자르지 않는다. 기능별 은은한 색은 hover 테두리와 오른쪽 위 윤곽 아이콘에만 쓰고 숨김·순서에 따라 바꾸지 않는다. 떠오르는 효과·다색 아이콘·큰 통계 블록은 쓰지 않는다.
- 개인별 탭 숨김은 홈 카드와 사이드바에 함께 적용하고 탭 관리에서 복원한다. 홈과 DB 관리 진입 경로는 항상 유지한다.
- DB 관리: 본문 상단의 공통데이터·기능별 설정·DB 원본 가로 탭, 그 아래 하위 탭과 편집 본문. 별도 DB 사이드 메뉴를 추가하지 않는다. 일반 기능 화면은 조회 전용(권역별 요청작업 작성·상태·담당 변경 예외), 원본 테이블은 읽기 전용이다.
- 로그인·회원가입: 왼쪽 44% 폼과 오른쪽 56% 브랜드 영역의 흰색 분할 화면. 왼쪽 위에 구름·COC dashboard, 폼은 최대 380px 중앙 정렬. 오른쪽에 `Cloud Operations Center` 한 줄과 그 뒤 낮은 불투명도의 같은 윤곽 구름(글줄 폭의 약 56%). 소셜 로그인·SSO·비밀번호 찾기·인용문·불필요한 하단 문구는 두지 않는다. 회원가입은 이름·이메일 아이디·비밀번호만 입력한다.

## 기능별 화면

- 인프라 자원: 제목 아래, 지표 카드 위에 국가 탭(전체 자원·KR·EU·NA 등)을 페이지 폭 밑줄 탭으로 두고 그래프와 자원 목록에 함께 적용한다. 상단은 Host·VM·Rack(Compute + Storage 합계)을 한 줄의 연결된 지표 카드로 표시한다. 왼쪽은 제목·28px 합계·설명, 오른쪽은 최대 56px 높이의 단색 미니 막대와 리전명이며 전체 높이는 약 150px다. Host는 남색, VM은 파랑, Rack은 인디고. 각 지표의 막대는 독립적인 최댓값을 쓰고 마우스 휠·트랙패드·키보드로 가로 스크롤하며 리전명은 9px로 줄임표 없이 표시한다. 0·미입력·미등록을 구별하고 가상의 증감률·기간 비교를 만들지 않는다. 자원 목록 표는 리소스 위치(리전·서비스)·컴퓨팅(Host·VM)·Rack(Compute Rack·Storage Rack)·운영 정보 그룹을 쓰고, 목록 제목과 검색·필터는 같은 행에 둔다. 기본 페이지 크기는 30개, 합계에 Σ 기호를 쓰지 않는다.
- 운영 인력: `features/staff/StaffTable.tsx`를 재사용한다. 흰 헤더와 가로 구분선, 약 50px 행과 셀 위아래 9px 여백. 국가·성명·직책·소속사·업무·근무지 열, 성명 옆 원형 사람 아이콘, 국가 배지 KR(파랑)·EU(청보라)·NA(슬레이트 블루). 국가 코드를 함께 표시해 색에만 의존하지 않는다.
- 리포트: 실제 기능 조회 화면을 한 열 전체 폭으로 재사용하며 인프라 자원 → 운영 작업 → 운영 인력 순서다(각 `feature.tsx`의 `report.order`). 인프라는 페이지당 15개, 작업 최대 15개, 인력 최대 10명을 보여 주고 각 전체 보기로 이동한다. 검색·필터·합계는 전체 원본에 적용한 뒤 개수를 줄인다. 변경 이력과 중복 요약 지표는 넣지 않는다.
- 권역별 요청작업: 페이지 맨 위에 전체·KR·NA·EU 리전 카드와 상태·TODAY 필터를 두고 리전별 전체·Open·In Progress·Completed 건수를 줄별로 표시한다. TODAY는 저장된 UTC 시각을 KST 날짜로 환산해 판정하고 해당 티켓에 영문 배지만 표시한다. 작업 시작 시간이 현재와 가까운 티켓을 먼저 둔다. 목록은 티켓 하나를 2행 그리드 카드로 표시한다. 왼쪽의 권역·상태 영역은 두 행을 병합하고 내부를 좌우로 나누되 권역 칸을 더 좁게 둔다. 작업 일정 칸은 아래 Requester 칸과 시작선을 맞춘다. 위에는 제목과 작업 일정, 아래에는 작업 내용, Requester, 담당자, 담당 권역을 둔다. 담당자 미지정은 담당자 칸만 회색으로 강조한다. Open은 빨강, In Progress는 파랑, Completed는 회색, TODAY는 검정 계열로 구분하고 제목만 최대 두 줄, 나머지는 한 줄로 표시한다. 상세는 화면의 약 90%를 쓰는 모달로 열며 아래 닫기 버튼은 창만 닫고 상태를 바꾸지 않는다. 상태는 수정 화면에서 사용자가 직접 고를 때만 변경한다. 조작 버튼은 닫기·수정·삭제로 단순화한다. 본문 편집기는 이미지·표의 행·열 추가·삭제와 전체 화면 편집을 제공한다.
- 리전·인력 내부 ID 열은 DB 원본 탭에만 표시한다. 공통데이터의 리전은 이름·국가, 인력은 이름만 표시·입력하며 선택 목록과 CSV도 이름을 쓴다.
- 공통데이터·기능별 관리자 편집에는 행 복사를 제공한다. 편집값만 새 초안으로 가져오고 PK·시각·비밀번호를 복제하지 않는다.
- 일반 화면에 조회 전용 문구, 안내용 하단 문장, 전체 사이트 푸터를 두지 않는다.

## 컴포넌트와 데이터

- `Panel`, `DataTable`, `Modal`, `Icon`, `FieldInput`과 공통 버튼·입력·배지 클래스를 재사용한다. 목록형 기능은 `SectionPage`(조회)·`SectionAdmin`(DB 관리 편집)·`RecordsAdmin`(목록 관리)을 먼저 검토한다. 기능마다 기본 컴포넌트를 다시 만들지 않는다.
- 데이터 표(Handsontable 기준): 헤더 `#edf4f8`, 셀 경계 `#cbdbea` 1px, 본문 `#182b3b`, 헤더 글자 `#172e46`. 본문 13px/18px, 행 높이 29px, 셀 여백 5px 8px, 그룹 헤더 22px. 모든 셀 경계와 행 번호를 유지하고 관련 열은 그룹 헤더로 묶는다. 수량은 우측 정렬·tabular-nums, 미입력은 `—`.
- 표의 검색·필터·정렬·총계·페이지 이동은 같은 툴바/푸터 패턴을 쓴다. 넓은 표는 표 영역 안에서 가로 스크롤하고 표 높이를 고정해 데이터를 잘라내지 않는다.
- 지표와 카드 건수는 실제 DB 데이터에서 계산한다. 샘플 수치를 코드에 고정하지 않는다.
- 버튼·입력·탭에는 hover, 키보드 focus, disabled, 필요하면 loading 상태를 제공한다. 아이콘 버튼에는 접근성 이름과 도움말을 지정한다.
- 모바일에서는 필터와 카드가 줄바꿈되고 표는 가로 스크롤한다. 모달은 화면 높이 안에서 스크롤한다. 인쇄 시 조작 UI는 숨긴다.

## 수정과 확인

1. 화면 구조와 재사용할 공통 컴포넌트를 먼저 정한다.
2. 공통 토큰으로 스타일을 적용하고 로딩·빈 값·오류·disabled 상태를 함께 구현한다.
3. 실제 데이터와 긴 문자열, 좁은 화면의 넘침, 키보드 focus와 읽기 흐름을 확인한다.
4. 프런트 빌드(TypeScript 검사 포함)와 필요한 서버 테스트 후 Docker에 반영한다.
