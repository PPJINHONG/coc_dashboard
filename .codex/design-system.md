# COC dashboard 디자인 규칙

향후 모든 기능과 관리 화면은 이 규칙과 기존 공통 컴포넌트를 따른다.

## 기본 표현

- 화이트 모드만 제공한다. `styles.css`의 색상·글꼴 토큰을 사용한다. 흰 패널, 옅은 회색 배경, 선명한 1px 청회색 테두리와 절제된 파란색 강조를 기본으로 한다.
- 영문·숫자는 자체 제공하는 `/fonts/InterVariable.woff2`를 사용한다. 한글은 같은 서버의 `/fonts/PretendardVariable.woff2`(Pretendard v1.3.9)를 사용해 맥·윈도우 모두 같은 파일로 표시한다. Inter를 먼저 선언해 영문·숫자를 유지하며 OS 설치 폰트나 외부 CDN에 의존하지 않는다. 모든 입력·버튼·표·모달도 같은 글꼴 규칙을 따른다. OFL 라이선스는 `public/fonts/Inter-LICENSE.txt`와 `public/fonts/Pretendard-LICENSE.txt`에 보관한다.
- 여백은 4/8px 배수, 패널 간격은 16~24px를 우선한다. 본문 13~14px, 표 12~13px, 보조 정보 11~12px를 기준으로 한다. 전체 텍스트는 검정·진한 남색(`#111d25`, `#142536`, `#1d334a`)만 사용한다. 설명·날짜·미입력·플레이스홀더·비활성 버튼에도 회색 글자나 opacity로 흐리게 하는 표현을 사용하지 않는다. 채운 파란색 버튼의 흰 글자와 오류의 진한 빨간색은 예외다.
- 강조·선택·연결·정상 상태에도 파란색 계열만 사용하며 초록·청록색은 사용하지 않는다. 실제 데이터 표의 청회색 셀 경계와 읽기 대비는 유지한다.
- 아이콘은 `components/Icon.tsx`의 SVG를 재사용한다. 이모지·무작위 색상·장식용 그라데이션·큰 그림자를 추가하지 않는다.

## 화면 구조

- 홈은 Supabase Integrations 참고 화면처럼 `COC dashboard` 제목·한 줄 설명, 주요 기능(넓은 인프라 미리보기와 리포트·이슈 카드), 3열 전체 기능 카드 목록으로 구성한다. 검색·별도 지표 박스·연결된 리전/저장 시간 박스는 배치하지 않는다. 홈 카드는 Handsontable 참고 이미지처럼 흰 배경, 1px 중립색 경계, 6px 모서리, 24px 안쪽 여백, 18px 제목·14px 설명을 사용한다. 카드 하단의 별도 색상 강조선은 두지 않고, 색 띠처럼 보이는 그림자 대신 낮은 불투명도의 부드러운 그림자를 두며 기존 오른쪽 위 윤곽 아이콘과 미리보기·문구·배치를 유지한다. 주요 기능 제목은 16px·설명은 12px로만 줄이며 강제 한 줄 처리나 문구 축약을 하지 않는다. 카드가 떠오르는 효과·이모지·다색 아이콘·큰 영어 카테고리·큰 통계 블록을 추가하지 않는다.
- 기능 화면: 좌측 사이드바, 상단 경로/액션, 제목, 필터·요약, 본문 순서. 사이드바는 접을 수 있으며 좁은 화면에서는 아이콘 중심으로 바뀐다.
- DB 관리: 본문 상단의 공통데이터·기능별 설정·DB 원본 가로 탭, 그 아래 하위 탭과 편집 본문을 배치한다. 편집 공간 옆에 별도 DB 사이드 메뉴를 추가하지 않는다.
- 일반 기능 화면은 조회 전용이다. 실제 활성 관리자만 DB 관리에서 업무 데이터를 편집한다. 원본 테이블은 읽기 전용이다.
- 개인별 탭 숨김은 홈 카드와 사이드바에 함께 적용하고 탭 관리에서 복원한다. 홈과 DB 관리 진입 경로는 항상 유지한다. 계정/브라우저별 표시 설정은 DB에 저장한다.

- 인프라 상단은 Host·VM·Storage을 한 줄의 연결된 지표 카드로 동시에 표시한다. 참고한 작은 막대 카드처럼 왼쪽은 제목·28px 합계·설명, 오른쪽은 최대 56px 높이의 단색 미니 막대와 리전명을 둔다. 전체 요약은 약 150px로 유지하며 큰 단독 차트나 전환 탭을 사용하지 않는다. Host는 남색, VM은 파랑, Storage는 인디고로 구분한다. 모든 수량은 실제 DB에서 계산하고 0·미입력·미등록을 구별한다. 가상의 증감률·기간 비교를 만들지 않는다. 항목별 막대 높이는 독립적인 최댓값을 사용한다. 각 지표의 그래프는 마우스 휠·트랙패드·키보드로 가로 스크롤하며 리전명은 9px로 줄임표 없이 모두 표시한다. 그래프 하단 안내 문구를 두지 않고 자원 목록 제목과 검색·필터는 같은 상단 행에 배치한다. 사이드바 및 인프라 자원·자원 목록 제목 옆에는 레코드 건수를 표시하지 않으며 상단 연결됨 표시도 두지 않는다. 좁은 화면에서는 조작부가 줄바꿈된다.

## 컴포넌트와 데이터

- `Panel`, `DataTable`, `Modal`, `Icon`과 공통 버튼·입력·배지 클래스를 재사용한다. 별도 화면마다 기본 컴포넌트를 다시 만들지 않는다.
- 표는 사용자가 제공한 Handsontable 사진을 기준으로 한다. 헤더 `#edf4f8`, 셀 경계 `#cbdbea` 1px, 본문 `#182b3b`, 헤더 글자 `#172e46`을 사용한다. 본문 13px/18px, 행 높이 29px, 셀 여백 5px 8px, 그룹 헤더 높이 22px로 촘촘하게 구성한다. 모든 가로·세로 셀 경계와 행 번호를 유지한다. 본문을 흐린 회색으로 처리하거나 과도한 셀 여백을 넣지 않는다. 관련 열은 그룹 헤더를 사용한다. 수량은 우측 정렬과 tabular-nums를 사용하고 미입력은 `—`로 표시한다.
- 표의 검색·필터·정렬·총계·페이지 이동은 같은 툴바/푸터 패턴을 사용한다. 넓은 표는 표 영역 안에서 가로 스크롤하며 페이지 전체가 넘치지 않게 한다.
- 지표와 카드 건수는 실제 DB 데이터에서 계산한다. 샘플 수치를 UI 코드에 고정하지 않는다.
- 버튼·입력·탭에는 hover, 키보드 focus, disabled, 필요한 경우 loading 상태를 제공한다. 아이콘 버튼에는 접근성 이름과 도움말을 지정한다.
- 모바일에서는 필터와 카드가 줄바꿈되고 표는 가로 스크롤한다. 모달은 화면 높이 내에서 스크롤한다. 인쇄 시 조작 UI는 숨긴다.

## 수정과 확인

1. 화면 구조와 기존 재사용 컴포넌트를 먼저 정한다.
2. 공통 토큰으로 스타일을 적용하고 로딩·빈 값·오류·disabled 상태를 함께 구현한다.
3. 실제 데이터와 긴 문자열, 좁은 화면의 넘침, 키보드 focus와 읽기 흐름을 확인한다.
4. TypeScript/프런트 빌드와 변경에 필요한 서버 검증 후 Docker에 반영한다.

- 인프라 표 기본 페이지 크기는 30개, 국가 필터는 KR·CN 등 코드로 표시하며 합계 표시에 Σ 기호를 사용하지 않는다. 일반 화면의 조회 전용 문구, 안내용 하단 문장과 전체 사이트 푸터는 표시하지 않는다. 표 높이를 고정해 데이터 영역을 잘라내지 않는다.
- 공통데이터·기능별 관리자 편집에는 행 복사를 제공한다. 복사는 편집값만 새 초안으로 가져오고 PK·시각·비밀번호·연결 댓글은 복제하지 않는다. 서비스 복사 시 새 코드를 필수 입력하고 리전은 이름·국가, 인력은 이름만 입력하며 계정 복사 시 새 아이디·비밀번호와 권한을 확인한다.

- 리전·인력 내부 ID 열은 DB 원본 탭에만 표시한다. 공통데이터의 리전은 이름·국가, 인력은 이름만 표시·입력하며 기능별 선택 목록과 CSV도 이름을 사용한다.

- 사이드바는 홈·리포트 순서를 고정하고 업무 기능을 뒤에 둔다. 변경 이력·DB 관리는 구분된 관리자 메뉴로 제공하며 일반 사용자 카드·탭 관리·리포트에 관리자 이력을 노출하지 않는다.
- 브랜드는 내부가 빈 하늘색 구름 SVG를 공통 아이콘의 같은 선 굵기로 사용한다. 홈 카드 외곽은 중립색으로 통일하고 기능 ID에 지정된 은은한 색을 hover 테두리와 윤곽 아이콘에만 적용한다. 카드 숨김이나 순서에 따라 색을 바꾸지 않으며 본문 배경은 흰색으로 둔다.

- 운영 인력 조회 표는 별도 `StaffTable`을 재사용한다. 흰 헤더와 가로 구분선만 사용하고 약 50px 높이의 행과 셀 위아래 9px 여백을 사용한다. 현재 국가·성명·직책·소속사·업무·근무지 컬럼을 유지하며 성명 옆 원형 사람 윤곽 아이콘과 국가 배지로 KR(파랑)·EU(청보라)·NA(슬레이트 블루)를 구분한다. 국가 코드를 함께 표시해 색에만 의존하지 않으며 글자는 진한 색을 유지한다. 편집용 입력 표와 다른 기능의 그리드 규칙은 유지한다.

- 리포트는 실제 기능 조회 컴포넌트를 한 열 전체 폭으로 재사용하며 인프라 자원 → 운영 작업 → 리전 이슈 → 운영 인력 순서로 표시한다. 변경 이력과 중복 요약 지표는 배치하지 않는다. 리포트에서 인프라 페이지당 15개, 작업·이슈 최대 15개, 인력 최대 10명을 표시하며 각 전체 보기로 이동한다. 검색·필터 및 합계는 전체 원본 데이터에 적용한 뒤 표시 개수를 제한한다.

- 로그인·회원가입은 왼쪽 44% 폼과 오른쪽 56% 브랜드 영역의 흰색 분할 화면을 사용한다. 왼쪽 위에 기존 구름·COC dashboard를 배치하고 폼은 최대 380px로 중앙 정렬한다. 오른쪽에는 `Cloud Operations Center`를 한 줄로 표시하고 그 뒤에 글줄 폭의 약 56%인 같은 윤곽 구름을 낮은 불투명도로 배치한다. 기존 Inter·Pretendard 및 파란색 토큰을 유지한다. 소셜 로그인·SSO·비밀번호 찾기·인용문·불필요한 하단 문구는 제공하지 않는다. 회원가입은 이름·이메일 아이디·비밀번호만 입력한다.
